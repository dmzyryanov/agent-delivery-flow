# agent-delivery-flow

Шаблон проекта с готовым агентным процессом поставки для Claude Code. Вы
даёте цель, агенты сами разбивают её на задачи, грумят, разрабатывают,
независимо проверяют и ревьюят, мержат и выкатывают. Человек нужен для
решений, а не для рутины.

Процесс перенесён целиком из QA Tools, где он месяц поставлял продукт до 1.0,
и переведён с GitLab на GitHub.

## Как начать

1. Склонируйте кит и откройте папку в Claude Code (лучше в desktop-приложении:
   там работают запланированные задачи):

   ```bash
   gh repo clone dmzyryanov/agent-delivery-flow
   ```

2. Запустите `/flow-init`. Скилл задаст один блок вопросов (у каждого есть
   ответ по умолчанию), создаст из шаблона новый репозиторий на GitHub,
   склонирует его рядом с китом и сохранит туда ваши ответы.
3. Откройте новую папку в Claude Code и запустите `/flow-init` ещё раз. Эту
   часть нужно делать в сессии самого проекта: только там действуют его
   настройки и Bash-гард, и только такую сессию видит очередь поставки.
   Скилл:
   - заполнит `.claude/flow.json`, `CLAUDE.md` и документы;
   - заведёт метки, настройки репозитория и, если план GitHub позволяет,
     правила защиты `main`;
   - проведёт первую поставку своих же настроек через PR, CI и очередь;
   - создаст две запланированные задачи: цикл поставки и груминг.
4. В той же папке отдайте цель в `/decompose`: «хочу сервис, который…».
   Скилл задаст вопросы, покажет план, а после вашего «да» заведёт эпик и
   мелкие задачи с зависимостями.

Дальше всё идёт по расписанию:

- **Груминг** каждые 15 минут берёт одну задачу, смотрит на неё глазами
  архитектора и тестировщика и дописывает план, затрагиваемые области и
  список атак. Мелкие невидимые пользователю баги и чоры он сам делает
  `state:ready`, остальные задачи оставляет с вопросами в `state:needs-owner`.
- **Вы** отвечаете на вопросы (`/groom` в чате) и ставите `state:ready`.
- **Цикл поставки** каждые 30 минут берёт готовую задачу и проводит её до
  конца. Одновременно разрабатывается до трёх задач, а мерж и выкатка идут
  по одной под общим замком. Каждая задача проходит через Developer,
  Tester, Reviewer и Codex (по желанию), затем мерж, проверку прогона `main`,
  smoke и тег версии.

## Что внутри

| Где | Что |
|---|---|
| `CLAUDE.md` | правила для всех сессий; проектные места заполняет `/flow-init` |
| `docs/DELIVERY.md` | процесс поставки целиком |
| `docs/DECISIONS.md` | решения, на которых процесс стоит, и почему |
| `.claude/flow.json` | настройки проекта: репозиторий, команды, деплой, версии, Codex, Figma, расписание |
| `.claude/agents/` | роли: developer, tester, tester-process, tester-look, reviewer, architect |
| `.claude/skills/` | `/flow-init`, `/decompose`, `/create-task`, `/groom` |
| `.claude/scheduled/` | сценарии запланированных запусков: `delivery-cycle.md`, `grooming.md` |
| `.claude/scripts/` | очередь и замок поставки, Bash-гард, preflight, отпечаток дерева, артефакт ревью, проверка перед запуском, Codex-ревью, проверка версии |
| `.claude/tests/` | тесты скриптов: `node --test .claude/tests/*.test.mjs` |
| `.github/` | CI (`ci.yml` на PR, `main.yml` на `main`: проверка → деплой → smoke), шаблоны задач и PR |

## Что нужно

- `gh`, залогиненный со скоупами `repo` и `workflow`; `git`; Node 20+.
- Claude Code: desktop-приложение для запланированных задач или `claude`
  для launchd.
- Docker — только если тестам проекта нужны база или сервисы.
- Codex CLI с входом через ChatGPT — только для внешнего ревью.
- Figma-коннектор — только если новые экраны рисуются в Figma.

## Что важно знать

- **Защита `main`.** В приватном репозитории на бесплатном GitHub правил
  защиты веток нет. Тогда пуш в `main` и мерж в обход очереди запрещает
  только Bash-гард. Настоящая защита есть у публичного репозитория или на
  GitHub Pro.
- **Папка запланированных задач.** Инструмент создания задач не умеет её
  задавать. После `/flow-init` откройте обе задачи в приложении и укажите
  папку проекта, без изоляции в worktree. Иначе задача запустится без
  настроек и гарда проекта.
- **Draft-PR.** В приватных репозиториях на GitHub Free и Pro черновиков
  PR нет. Тогда процесс открывает обычный PR с префиксом `Draft: ` в
  заголовке и снимает префикс перед мержем (`delivery.draftPullRequests`).
- **Режим Auto.** Запланированная сессия стартует в режиме из
  `~/.claude/settings.json`. Если там не `auto`, первый же запрос
  разрешения остановит её на часы. `/flow-init` спросит, ставить ли его.
- **Стоимость простоя.** Задачи desktop-приложения открывают сессию на каждый
  запуск, даже когда работы нет. Дешевле launchd: проверка
  `fire-check.mjs` вообще не тратит токены, если работы нет
  (`docs/tooling/scheduled-fires.md`).
- **Тесты.** Из QA Tools перенесены тесты поведения скриптов. Тесты, которые
  закрепляли формулировки процедур, заменены одной проверкой
  согласованности `flow-consistency.test.mjs`.
